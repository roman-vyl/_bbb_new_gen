# ADR-004 — Parquet Export / Read Model

- **Status:** OPEN (stub)
- **Decision gate for:** Phase 8 — Exports & Polish
- **Author / owner:** TBD
- **Date opened:** TBD
- **Date decided:** —

> Этот ADR — **заглушка**. Будет наполнен и закрыт перед стартом Phase 8 — но только тогда, когда research реально упрётся в скорость SQLite или в потребности `vectorbt-pro`. До этого Parquet остаётся в DEFERRED. Конкретные пути, схемы партиционирования, выбор компрессии в этом стабе сознательно не фиксируются.

---

## 1. Проблема

В Phase 8 появляется экспорт данных в Parquet — для тяжёлой research-работы вне SQLite. Источник правды остаётся в SQLite; Parquet — это снимок, перестроенный из SQLite.

## 2. Зачем нужно решение

- Без формы дерева экспорта Phase 8 не может стартовать: непонятно, что именно строится и как это потом ест потребитель (`vectorbt`/`vectorbt-pro`).
- Форма экспорта влияет на схему файлов индикаторов (см. ADR-002), на политику обновления снимков и на ожидания потребителей. Решать это «как-нибудь по ходу» дороже, чем закрыть ADR.

## 3. Какие вопросы должен закрыть ADR

- **Структура дерева экспорта.** Партиционирование (Hive vs другое), раскладка по символу/таймфрейму/году, единое или раздельное дерево для свечей и индикаторов.
- **Триггер экспорта.** По требованию (CLI-команда), по расписанию, по событию — и атомарность записи (как избежать partial-snapshot).
- **Версионирование снимков.** Перезапись или поколения с timestamp в имени.
- **Поведение для warmup/error-рядов индикаторов.** Фильтрация на экспорте или экспорт со статус-колонкой — потребитель Parquet не должен случайно получать NaN без предупреждения.
- **Контракт с потребителем (`vbt.ParquetData` или аналог).** Что именно он ест, какие колонки/типы, как маппится временная колонка.
- **Компрессия.** Какой алгоритм по умолчанию.

Конкретные пути, имена партиций, выбор компрессии, целевые tolerance round-trip-теста — это уровень финальной версии этого ADR.

## 4. Связь с другими решениями

- ADR-002 — схема `indicators` (форма ряда напрямую влияет на схему Parquet-файла индикаторов).
- DECIDED в мастер-плане: `open_time_ms` (INTEGER, ms UTC) как единственная временная колонка; SQLite — источник правды (обратное направление Parquet → SQLite не делаем).

## 5. Когда закрывается

Перед стартом Phase 8 (после `phase-7-done`), и только при наличии реального сигнала боли — иначе Phase 8 целиком остаётся в DEFERRED.
