# Phase 8 — Exports & Production Polish (phase card / заглушка)

> Короткая phase card, не детальное ТЗ. Конкретные пути экспорта, компрессия, длительность stability-run-а, list of CI-проверок — это уровень детального ТЗ Phase 8, написанного **после** закрытия ADR-004.

## Цель

Снимки данных для тяжёлой research-работы вне SQLite + production polish.

## Прикладной результат

Финиш слоя данных: можно строить торговые стратегии, не оглядываясь на надёжность данных.

## Зависимости

- Phase 7 (стабильный multi-symbol сервис + read-only API + daily integrity).

## Decision gates (обязательно до старта реализации)

- **ADR-004** — Parquet export/read model: структура дерева экспорта, частота снимков, правила для warmup/error-рядов индикаторов, контракт с потребителями.

## Что не делать раньше Phase 8

- `pyarrow`/Parquet — не появляется в `pyproject.toml` до Phase 8.
- CI-pipeline (lint/типы/полные прогоны на PR) — до Phase 8 нет.
- Production-полировки и многодневные stability-run-ы — Phase 8.

## Что точно не трогать в Phase 8

- **Не менять схему SQLite ради Parquet.** Parquet адаптируется к существующей схеме, а не наоборот.
- **Не делать обратный путь Parquet → SQLite.** Источник правды — SQLite; Parquet это только снимок.

## Ключевые открытые вопросы

- Структура дерева экспорта и его связь с `vectorbt`/`vectorbt-pro` (как именно потребитель ест дерево). → ADR-004.
- Частота снимков и поведение при partial-write. → ADR-004.
- Что делать с warmup/error-рядами индикаторов в Parquet (фильтровать на экспорте или отдавать со статусом). → ADR-004.
- Какие именно проверки попадают в CI и каков срок и масштаб финального stability-run-а — детальное ТЗ Phase 8.

## Что появляется на уровне намерения (без файлов и тестов)

- экспортёр Parquet и CLI-команда запуска экспорта;
- короткий README с инструкцией поднять проект с нуля;
- финальная версия `docs/api.md`;
- CI-pipeline с базовыми проверками;
- финальный stability-run и приложенный отчёт.

Конкретные пути экспорта, компрессия, формат имён файлов, точное расписание snapshot-ов, список CI-проверок и длительность stability-run-а — **уровень детального ТЗ Phase 8**, не уровень мастер-плана и не уровень этой phase card.
